# Implementation Plans

Generated by the improve skill on 2026-10-12 (audit at commit `bcc721dfd`,
upstream base v0.73.0). Execute in the order below unless dependencies say
otherwise. Each executor: read the plan fully before starting, honor its
STOP conditions, and update your row when done.

The audit ran non-interactively, so plans were written for the top five
findings by leverage (impact ÷ effort, discounted by confidence). The
remaining vetted findings are listed under "Vetted, not yet planned"; ask
for a plan by number.

Scope of the audit: the fork-owned surface (everything under `linux/`, the
fork-owned Swift in `Sources/CodexBarCore/MachineSync`, `Sources/CodexBarCLI/CLISync*`,
`CostUsageSpendBucket.swift`, `OpenCodeLocalUsageReader.swift`,
`RPCStderrTail.swift`, the allowlisted hook edits, and the fork-only
workflows). Upstream Swift code outside those files was not audited; findings
there belong to steipete/CodexBar (#62).

## Vetted, not yet planned (ask for a plan by id)

Ordered by leverage. Confidence is HIGH unless noted.

- **E3** Antigravity enrichment runs `ss`/`pgrep`/`lsof`/`curl` synchronously
  on the compositor thread on every `/usage` poll (`extension.js:246-354`,
  called at `:2441`); it also POSTs with `curl -k` to every local listener
  matching `agy|language_server|antigravity` and treats a missing
  `remainingFraction` as 0 % used. The CLI already probes the same quota
  endpoint (`AntigravityStatusProbe.swift`). Fix: delete the JS probe if the
  CLI output matches, else make it async. M, conflicts with PR #110.
- **E5** The Refresh button sends `/usage?fresh=1` but serve has no handler
  for `fresh` (`grep -rn '"fresh"' Sources/` finds nothing), so a manual
  refresh inside serve's cache TTL returns cached data behind a spinner.
  Fix: implement `fresh` in `CLIServeCommand.swift` (an allowlisted hook
  file; adds a line to `hook-allowlist.tsv`) and propose it upstream, or
  drop the flag and the spinner. S–M.
- **S1** Machine Sync push: non-transient errors (403 `machine_limit`,
  `enrollment_expired`, an oversized day blob > 64 KiB) get no backoff, a
  failing day blob prevents the `profile` heartbeat, and while backfilling
  every failed cycle rescans the whole retention window
  (`MachineSync.swift:236-248, 292-325`; `MachineSyncEnvelope.swift:53`).
  No test covers 413/oversize or post-pair `machine_limit`. M, MED on how
  often a day exceeds 64 KiB.
- **R4** Final-release-only assets (`usagebar_*.deb`, `usagebar-*.rpm`,
  SRPM) are not checked by `verify-assets.sh` (`:236-246` lists CLI, tray,
  extension only) and never install-tested; `smoke-cli.sh` never starts
  `serve`. 1.1.0 final will be the first run of that path. M.
- **E6** The ~625-line UI-smoke harness (`_scheduleUISmoke`,
  `extension.js:2654-3279`) ships in the production extension, gated only by
  the `USAGEBAR_UI_SMOKE_RESULT` env var; it screenshots the stage and
  writes to an env-supplied path. Move it to `uismoke.js` loaded by dynamic
  import; `ego-zip.py` then leaves it out of the store zip. Relevant to #77/#78. S–M.
- **R6** `linux/test-devkit-ui.sh:23-25` and `linux/run-dev.sh:8-9` repoint
  the developer's real `~/.local/share/gnome-shell/extensions/usagebar@…`
  symlink at the checkout and never restore it (this has already bitten the
  maintainer). Use a temporary `XDG_DATA_HOME` inside the session. S.
- **S3** `sync.json` (holds the Pairing Link = group root key) is written
  with `Data.write(.atomic)` and chmod'ed to 0600 afterwards
  (`MachineSyncStore.swift:113-123`); the lock file is opened without
  `O_NOFOLLOW`. Upstream's `CredentialFileWriter.writePrivate`
  (`CredentialFileWriter.swift:29`) does it right. S, MED (temp-file mode
  unverified without a toolchain).
- **S2** `sync create` POSTs to the server before saving the only copy of
  the key (`MachineSync.swift:93-106`); a failed save after a 2xx burns the
  single-use Enrollment Token. S.
- **E16** About shows "codexbar CLI unknown" for script installs:
  `cliVersion` (`extension.js:1240-1251`) joins `dirname(link)` with an
  absolute symlink target (`GLib.build_filenamev` does not reset on absolute
  paths; verified with gjs). Prefs already uses the tested `parseCliVersion`.
  Also duplicated `findBinary`, two "ago" formatters, two token formatters. S.
- **E4** `_fetchJSON` (`extension.js:2210-2233`) calls the callback a second

- **E11** The Enrollment Token travels in argv (`syncprefs.js:29-33`,

## Findings considered and rejected

- Bearer-token leak on cross-host redirect in `MachineSyncClient`: upstream's
  `ProviderHTTPRedirectGuardDelegate` (`ProviderHTTPClient.swift:212-247`)
  already refuses non-https and cross-origin redirects.
- CSRF-style `POST /sync/push` from a local browser: the push is idempotent,
  holds the lock and makes no network call when nothing changed; serve's
  Host allowlist blocks DNS rebinding.
- Authenticating the extension to its own serve child: needs a serve-side
  change in an upstream file; the realistic risk (a foreign loopback
  listener spoofing usage) is spoofing/DoS only. Plan 003's per-spawn port
  removes the "stuck on a taken port" half of it.
- `.sha256` fetched from the same origin as the tarball: standard GitHub
  release practice; attestations (R5) are the real upgrade.
- ESLint warning-only in CI: the tree has 12 style warnings and no
  correctness ones; making it blocking is a one-line change worth bundling
  into T1, not a finding on its own.
- Fork cache schema numbers (Claude 6, Pi 10) colliding with a future
  upstream bump: LOW confidence, no observed bug; revisit only if an
  upstream merge resolves to the same numbers.
- "No default Sync Server", "no plaintext sync mode", "no sync-server
  subcommand": settled by ADR 0002, 0001 and 0003.
- Shipping provider logos in the store build / a CLI auto-updater in the
  extension: deliberately removed (trademarks; PR #91).
- `install-cli.sh` running the downloaded binary (`--version`) before
  linking: it runs after checksum verification; by design.
